# GitHub Actions CI/CD Test Project

![CI/CD Pipeline](https://github.com/username/repo228/workflows/CI/CD%20Pipeline/badge.svg)

Тестовый проект для демонстрации возможностей GitHub Actions с автоматическим тестированием, проверкой безопасности и развертыванием.

## 🚀 Возможности

- **Автоматическое тестирование** на нескольких версиях Node.js (18.x, 20.x, 22.x)
- **Проверка качества кода** с помощью ESLint
- **Покрытие кода** с отчетами в Codecov
- **Аудит безопасности** зависимостей
- **Автоматическое развертывание** на staging при push в main
- **Создание артефактов** сборки

## 🛠️ Установка и запуск

### Требования

- Node.js 18.x или выше
- npm или yarn

### Локальная установка

```bash
# Клонирование репозитория
git clone https://github.com/username/repo228.git
cd repo228

# Установка зависимостей
npm install

# Запуск приложения
npm start
```

### Доступные команды

```bash
# Запуск тестов
npm test

# Запуск тестов с отслеживанием изменений
npm run test:watch

# Запуск тестов с покрытием кода
npm run test:coverage

# Проверка качества кода
npm run lint

# Автоматическое исправление ошибок линтера
npm run lint:fix

# Запуск сервера
npm start
```

## 🌐 API Endpoints

### GET /
Возвращает приветственное сообщение

**Пример ответа:**
```json
{
  "message": "Hello World! GitHub Actions работает!"
}
```

### GET /health
Проверка состояния сервера

**Пример ответа:**
```json
{
  "status": "OK",
  "timestamp": "2025-09-13T10:30:00.000Z"
}
```

### GET /add/:a/:b
Сложение двух чисел

**Параметры:**
- `a` - первое число
- `b` - второе число

**Пример запроса:**
```
GET /add/5/3
```

**Пример ответа:**
```json
{
  "a": 5,
  "b": 3,
  "result": 8
}
```

## ⚙️ GitHub Actions Workflow

### Триггеры

Workflow запускается при:
- Push в ветки `main` или `develop`
- Создании Pull Request в ветку `main`

### Jobs

#### 1. **Test** 
- Тестирование на Node.js 18.x, 20.x, 22.x
- Проверка линтером
- Запуск тестов с покрытием кода
- Отправка отчета покрытия в Codecov

#### 2. **Security**
- Аудит безопасности зависимостей
- Проверка на известные уязвимости

#### 3. **Build**
- Проверка сборки приложения
- Тестирование запуска сервера
- Создание артефактов

#### 4. **Deploy**
- Развертывание на staging (только для main ветки)
- Загрузка и использование артефактов

### Переменные окружения

Workflow поддерживает следующие переменные:

| Переменная | Описание | Обязательная |
|------------|----------|--------------|
| `CODECOV_TOKEN` | Токен для Codecov | Нет |
| `PORT` | Порт для запуска сервера | Нет (по умолчанию 3000) |

## 🧪 Тестирование

### Структура тестов

- **Модульные тесты** (`tests/math.test.js`) - тестирование математических функций
- **Интеграционные тесты** (`tests/api.test.js`) - тестирование API endpoints

### Покрытие кода

Проект настроен для сбора метрик покрытия кода:

```bash
npm run test:coverage
```

Отчеты сохраняются в папке `coverage/` и автоматически отправляются в Codecov при CI/CD.

## 🔧 Конфигурация

### ESLint

Проект использует ESLint для проверки качества кода с правилами:
- Отступы: 4 пробела
- Кавычки: одинарные
- Точки с запятой: обязательны
- Unix line endings

### Jest

Настройки тестирования:
- Окружение: Node.js
- Сбор покрытия для всех JS файлов
- Исключение папок `node_modules` и `coverage`

## 🚀 Развертывание

### Staging

При push в ветку `main` автоматически происходит развертывание на staging окружение.

### Production

Для production развертывания рекомендуется:

1. Создать отдельный workflow или environment
2. Добавить manual approval для production
3. Настроить секреты для production сервера

```yaml
environment: production
```

## 🔍 Мониторинг

### Статусы Build

- ✅ Зеленый бейдж - все тесты проходят
- ❌ Красный бейдж - есть падающие тесты
- 🟡 Желтый бейдж - тесты в процессе выполнения

### Метрики

- Покрытие кода через Codecov
